## ЛР3 — координаты поездок и FIFO worker pool

Добавлены приём координат и чтение маршрута. Активные поездки без свежих координат теперь находятся сканером PostgreSQL и через ограниченную очередь и постоянный пул воркеров получают `REQUEST_POSITION` от учебного Push Service.

### Реализация

```text
PostgreSQL → сканер по тикеру → FIFO-канал → фиксированный пул → HTTP Push
POST positions → транзакция → COMMIT → отмена ожидающей задачи + метрика
```

- Миграции `00004` и `00005`: `last_position_at`, `trip_positions` и частичный индекс устаревших активных поездок.
- `POST positions` атомарно сохраняет точку и обновляет последнее время через `TxManager`; опоздавшие точки его не уменьшают. `GET positions` сортирует по `recorded_at, id`, пустой маршрут — `{"positions":[]}`.
- Один последовательный сканер, неблокирующая постановка с `queued / duplicate / dropped`. Переполнение не останавливает обход; поездка может попасть в очередь на следующем тике.
- Дедупликация охватывает ожидающие и выполняемые задачи. После коммита координаты ожидающая задача отменяется; старая запись в канале не выполняет и не удаляет новую задачу той же поездки.
- Одна попытка Push на задачу, собственный HTTP-клиент и таймаут. Ошибки сети и статусы сервера различаются, тело ответа закрывается. Передаются водитель, поездка и `request_id`.
- Остановка: HTTP → сканер → доработка очереди → клиенты и БД, в общем `SHUTDOWN_TIMEOUT`. После рестарта выборка возобновляется из БД без прогрева.
- Все метрики ЛР3, отдельный спан Push и span link от задачи к сканированию.

### Конфигурация

`POSITION_CHECK_INTERVAL=30s`, `POSITION_STALE_AFTER=60s`, `POSITION_WORKERS=4`, `POSITION_QUEUE_SIZE=100`, `PUSH_REQUEST_TIMEOUT=1s`; обязательный `PUSH_HTTP_URL` берётся из `.env`. Общий `SHUTDOWN_TIMEOUT=10s` переиспользован. Отдельный cooldown не хранится: повтор возможен при следующей постановке сканером после завершения задачи.

### Проверки

- Все unit-тесты дважды с `-race`, `goleak`, управляемым тикером и виртуальным временем; линтер — 0 issues.
- PostgreSQL-интеграция и сквозной тест контейнера дважды с `-race` на окружении курса.
- Покрытие домена и пяти usecase — 100%, фоновых компонентов — 94,8%, Push-гейтвея — 95,7%.
- Живой прогон на окружении курса 25.11.2026: молчащая поездка опрашивается каждые ~5 с; свежая и завершённая — без Push. Для измерения использованы интервалы 5/10 с, 2 воркера и очередь 10.
- 200 активных поездок, задержка Push 5 с и таймаут 1 с: сканер продолжает работу, `dropped` растёт, бизнес-ручки отвечают максимум за 13,824 мс. Максимальное наблюдавшееся завершение по SIGTERM — 5,660 с при бюджете 10 с. После рестарта опрос тех же активных поездок возобновляется.
- Задержка заглушки сброшена, собственные схемы удалены.
